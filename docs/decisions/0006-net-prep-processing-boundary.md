# ADR 0006：净配菜加工边界

## 状态

已接受，2026-08-20。

## 背景

Nora 服务的工厂交付生鲜净菜、肉类前处理品、分隔辅料和净菜组合包，生产责任在分装、复核和冷链暂存后结束。早期样例把最终加热步骤、热厨工位和高温质量参数混入 BOM、排产、MES 与 Showroom，导致配方语义、成本口径和用户预期都偏离真实业务。

## 决策

1. 活动工序类型只允许 `receive/wash/cut/marinate/mix/cool/pack/quality`。
2. 允许表达来料验收、低温解冻、清洗、挑拣修整、切配、腌制、称重组配、分装、包装、复核和冷链暂存。
3. 禁止生成炒、蒸、煮、炸、煎、烤等最终加热步骤；禁止热菜、热厨、灶台及其产线、工位、设备、温度曲线和制熟质量指标。
4. 该限制同时适用于领域模型、PostgreSQL/Prisma 枚举、DTO、快照、BOM、工艺模板、订单商品、工单、Mock、seed、测试、Dashboard、MES、数字孪生和 Showroom。
5. 按某道菜命名的商品必须明确标为“某某净菜包”或“某某配菜包”，表示待客户后续处理的原料组合，不能展示为本工厂已制熟的菜品。
6. 新需求若确实涉及最终加热制作，应进入独立产品与上下文决策，不能扩展现有 `Recipe & Process` 枚举或借用 Demo 绕过本 ADR。

## 后果

- BOM 逻辑表和流程视图更贴近净配工厂的真实核对任务。
- 排产、MES 和质量示例使用切配、组配、包装、冷链温度与净重指标。
- 客户若同时运营熟食厨房，需要独立建模和单独评估法规、设备、HACCP 与成本边界；当前 Nora 不覆盖。

## 迁移

- 前向 migration 从活动数据库枚举中移除旧的最终加热类型。
- 仅 `NORA-DEMO` 组织的确定性样例可自动纠正为称重组配或复核称重，并写入 BOM 版本事件。
- 非演示组织一旦存在相关工序或审批快照，migration 必须失败关闭，由数据所属组织在保留审计和不可变生产依据的前提下制定专门迁移。
- 已提交的历史 migration 和历史审计报告保持原样，作为问题来源与修复证据，不再代表当前能力。

## 验证

- Prisma 与 PostgreSQL 的 `BomOperationKind` 只有八个净配类型。
- DTO 和快照校验拒绝白名单外类型。
- seed、Mock 与所有可运行页面不出现最终加热步骤、热菜产线或高温制熟指标。
- 文档链接检查、类型检查、单测、API 构建、Web 构建、空库 migration、重复 seed 和 smoke 全部通过。

## 恢复

回退应用时不恢复已移除的工序类型。数据库恢复使用部署前备份；若未来产品决定覆盖最终加热制作，必须用新的 ADR、领域上下文、迁移和完整验收重新引入，不能撤销本迁移来隐式开启。
