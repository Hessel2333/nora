# ADR-0008：领出物料核销不重复改变库存余额

状态：已接受
日期：2026-08-21

## 背景

Nora 的领料命令已经追加 `issue/outbound` 库存流水并扣减原库位余额。现场仍需要记录已领批次实际耗用、报损或退料的去向。如果把实际耗用或现场报损再次记为出库，会对同一物料重复扣减库存；如果只覆盖领料流水，又会破坏审计和批次追溯。

## 决策

- 新增不可变的 `WorkOrderMaterialUsage` 执行事实，处置类型为 `consumed` 或 `scrapped`，绑定组织、工单、产品、原库存批次、原库位、数量、单位、原因、操作者、工位、设备、幂等键和服务端时间。
- 实际耗用和现场报损表示“已经从库存领出的物料在生产现场如何处置”，不新增库存流水，也不修改库存余额。
- 退料仍由 Inventory 追加 `return/inbound` 流水并增加原库位余额；可退数量等于同批次领料减退料、耗用和报损。
- Execution 拥有实际耗用和报损事实；Inventory 拥有领退料台账和余额。工单物料页面是跨上下文只读投影，使用文档化 ID 组合两类事实。
- 报产前由服务端验证每类冻结叶子原料净领用等于计划，且净领用全部归入耗用或报损，未使用部分必须先退料。
- 首版不支持核销事实的修改、删除或反向纠错；发现错误时停止下游报产并由后续追加式纠错能力处理。

## 后果

- 库存余额继续只由库存台账推导，不会因领料和实际耗用重复扣减。
- 成品批次可通过工单追溯到实际耗用/报损原料批次，而不仅是“曾经领过”的批次。
- 现场必须完成物料去向后才能报产，操作步骤增加，但能显式暴露遗留余料和损耗。
- 超计划投料、替代料、核销纠错、工序级投料与实际成本仍需要后续设计，不能通过修改本表历史解决。

## 验证

- 数据库约束保护正数 Decimal、报损原因、组织内幂等和不可变核销事实。
- Service 测试覆盖超量、重复提交、非法状态、跨组织、单位冲突，以及核销与退料共享锁后的边界。
- 报产测试覆盖未领齐、存在待核销量和完整核销三种路径。
- 从空库执行 migration、重复 seed，并核对领料后余额、核销后余额不变、退料后余额增加。
- 浏览器检查桌面和移动端的耗用、报损、退料及报产阻断提示。

## 恢复与迁移

历史工单不把既有领料推断为实际耗用，也不自动回填核销。若发布后发现问题，停止新的核销和报产写入，保留已追加事实；代码与结构回退使用后续 migration，不删除或改写核销记录。
