# ADR-0001：订单采用自动校验与例外人工审核

状态：已接受
日期：2026-08-18

## 背景

订单审核的目的不是让某个负责人机械点击一次，而是在客户承诺进入生产系统前识别商业和履约例外。若所有订单都强制人工点击，稳定订单会形成无价值积压；若所有订单都自动通过，异常价格、紧急交期、特殊规格和导入错误可能直接进入生产需求。

## 决策

采用“系统自动校验 + 正常订单自动批准 + 例外订单人工审核”的混合模式。

订单提交后由审核策略产生三种结果：

| 结果 | 含义 | 后续动作 |
| --- | --- | --- |
| `blocked` | 基础数据不合法，系统不能接受 | 保持草稿或退回提交人修正 |
| `manual_review` | 订单有效，但存在需要业务判断的例外 | 进入订单审核队列 |
| `auto_approve` | 全部规则通过且风险在自动放行范围内 | 系统批准并创建生产需求 |

自动批准与人工批准必须调用同一个批准用例，执行相同的状态迁移、生产需求创建、幂等约束和审计记录。自动批准不能绕过业务事务。

## 角色边界

| 角色 | 责任 |
| --- | --- |
| 订单录入员 / 客服 / 销售 | 创建、修改并提交订单；不能批准自己制造的业务例外 |
| 系统审核策略 | 执行确定性检查，给出结果、原因代码和策略版本 |
| 订单运营 | 处理常规例外，如导入异常、交期确认、数量或配送信息异常 |
| 销售主管 | 处理价格、合同、信用和重要客户例外，并拥有业务覆盖权限 |
| 生产计划员 | 对产能、生产窗口、BOM 和工艺可行性提供意见；不负责确认客户商业条款 |
| 老板 / 管理员 | 查看全局风险和审计，必要时升级处理；不作为日常审核默认角色 |

小型组织可以由同一账号兼任订单运营和销售主管，但系统仍应记录其执行时使用的角色。

## 人工审核重点

人工审核只判断自动规则无法确定的例外：

1. 客户承诺是否真实、完整且在合同范围内。
2. 商品、规格、数量、价格和配送要求是否存在非标准内容。
3. 交期是否需要与客户或生产侧再次确认。
4. 缺少 BOM、特殊标签、过敏原或客户隔离要求应如何处理。
5. 是否允许覆盖规则，以及覆盖原因和责任人是否完整。

生产计划如何合批、拆批、选择班次或生成工单，不属于订单审核决定。

## 分阶段落地

### 当前 MVP

- 自动执行基础数据和 BOM 就绪检查。
- 所有有效订单暂时进入人工审核队列。
- 人工批准创建一张生产需求，不直接生成生产计划或工单。
- 缺少 BOM 可以确认客户需求，但生产需求必须保持待处理，不能进入排产。

### 混合审核阶段

- 增加版本化审核策略和组织级阈值配置。
- 低风险订单在提交事务中自动批准。
- 审核列表只展示 `manual_review` 订单，并显示触发原因和建议处理人。
- 对策略结果、人工覆盖和批准方式进行完整审计。

## 后果

- 日常订单不再依赖无意义的人工点击。
- 人工精力集中在真正影响客户承诺和履约的例外。
- 需要新增审核评估记录、原因代码、策略版本、执行角色和配置管理。
- 在上述数据和权限能力完成前，自动批准保持关闭，避免出现不可解释的自动决策。
