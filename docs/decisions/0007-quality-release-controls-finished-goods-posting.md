# ADR-0007：质量放行控制成品入账与工单完工

状态：已接受
日期：2026-08-21

## 背景

工单已经有执行状态和领退料库存流水，但尚无实际产出、质量判定或成品入库事实。若报产时直接增加可用库存，不合格品会提前可用；若质量、库存和工单分别提交，失败或重试会产生状态不一致。

## 决策

- 报产创建 `WorkOrderOutput.pending_quality` 和 `InventoryLot.pending`，工单与生产批次进入 `awaiting_quality`，但不创建库存流水或余额。
- 质量检查是追加式记录，保存标准版本、抽样、测量、检查项、判定、真实操作者、工位、设备和服务端时间。
- 合格放行在一个 Serializable 事务中完成：追加质量检查、放行库存批次、追加 `produce/inbound` 流水、更新余额、完成工单和生产批次，并追加审计事件。
- 不合格判定不创建库存流水，将批次置为 `rejected`，工单和生产批次置为 `exception`。恢复后可申报新产出，旧历史不可覆盖。
- 报产时复制工单冻结配方末道工序的温度上下限；质量判定不读取最新 BOM。无冻结温度范围时仍记录实测值和人工检查，但不虚构温度阈值。
- 首版每张工单同一时间最多一个待检产出，最多一个放行产出；不实现多次部分报产累计完工。

## 后果

- 待检品不是库存余额，不会被默认当作可用成品。
- 库存账、质量记录和生产状态共享同一事务与幂等语义，可从成品批次追溯到工单、冻结配方和来源订单。
- 不合格后的返工、报废或让步接收仍需后续工作流；当前只能保留拒收事实、进入异常并在恢复后申报新批次。
- 质量标准主数据尚未建立；首版只保存真实使用的标准版本标识与检查结果，不能宣称自动质量判定。

## 验证

- 数据库约束保护正数 Decimal、唯一批次、组织内幂等、产出/流水因果链和不可变质量检查。
- Service 测试覆盖合格、不合格、重复提交、非法状态、revision、跨组织与事务失败。
- 从空库执行全部 migration，重复 seed，并核对放行前后流水与余额。
- 浏览器检查桌面和移动端的报产、判定、冲突、离线与 production 只读状态。

## 恢复与迁移

历史工单不回填虚构产出。代码回滚不删除已产生的质量或库存事实；数据库结构回退只能通过后续 migration。若发布后发现异常，停止新的报产/判定写入，保留现有记录并通过追加纠错能力恢复。
