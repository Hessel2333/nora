# 订单审核页面流

## 用户任务

订单运营或销售主管处理系统无法自动判断的订单例外，决定批准客户需求或退回修改。

## 入口与出口

| 场景 | 入口 | 页面主动作 | 完成后去向 |
| --- | --- | --- | --- |
| 人工审核 | `/orders/approvals` | 批准并创建需求 / 退回修改 | `/orders/approvals` |
| 查看订单 | `/orders` | 查看订单详情 | 返回 `/orders` |
| 从详情了解审核结果 | `/orders/:id` | 查看审核记录和生产需求 | 保持订单详情 |
| 直接打开审核 URL | `/orders/:id/review` | 审核或退出 | 默认返回 `/orders/approvals` |

审核页面不得根据浏览器历史决定业务返回目标；历史中可能包含搜索、刷新或外部入口。返回地址应由当前任务类型确定。

## 页面信息顺序

1. 订单号、客户、交期和金额。
2. 商品、数量和当前有效 BOM。
3. 自动检查结果与需要人工判断的例外原因。
4. 历史操作和策略评估记录。
5. 审核决定、意见和动作后果。

正常订单在混合审核阶段不会进入此页面。人工审核页应突出“为什么需要我处理”，而不是让审核人重新检查所有已经通过的机器规则。

## 动作反馈

- 批准成功：回到审核列表，提示订单号、生产需求编号和“已进入待计划”。
- 退回成功：回到审核列表，提示订单号和退回原因。
- 并发冲突：保留页面输入，提示订单已变化并要求刷新，不自动覆盖。
- 事务失败：订单保持待审核，不显示已成功或部分成功。

## 文案约束

- 使用“审核通过并创建需求”，不得写成“生成生产单”。
- 使用“返回订单审核”，不得使用“返回订单详情”作为审核任务默认出口。
- 缺少 BOM 时明确说明“可以确认客户需求，但暂不能进入生产计划”。
- 自动批准记录显示“系统按策略自动批准”，并展示策略版本和命中规则。
