# 生产工单现场状态控制功能规格

## 目标

现场班组长或操作员在明确的工位和设备上下文中，对已释放工单执行开始、暂停、继续、上报异常和恢复，并让生产批次状态与审计记录保持一致。

## 当前问题

工单由生产批次释放后只能查看。现场无法记录何时开工、为何暂停、由谁在哪个工位上报异常，生产准备页也无法区分“已释放”和“正在执行”。

## 用户与权限

| 角色 | 可执行动作 | 数据范围 |
| --- | --- | --- |
| 现场操作员 | 开始、暂停、继续、上报异常 | 当前组织、授权工位和设备 |
| 班组长 | 异常恢复为待开工或生产中 | 当前组织、授权工位和设备 |
| 生产主管/计划员 | 查看状态和审计 | 当前组织 |

当前 production 尚未接入可信身份和权限，所有正式写命令继续失败关闭；development 使用明确开发身份验证完整事务，demo 仅使用隔离浏览器状态。

## 核心用例

1. 操作员在生产工单页开始一张待开工工单。
2. 服务端校验组织、状态、revision、幂等键、工位和设备上下文。
3. 服务端在同一事务中更新工单和来源生产批次，并分别追加审计事件。
4. 暂停和异常必须填写原因；异常恢复必须填写处置说明并选择恢复到待开工或生产中。
5. 相同幂等键重试返回同一业务结果，不重复转换或增加事件。

## 页面入口与出口

| 用户任务 | 入口 | 成功出口 | 取消/返回 |
| --- | --- | --- | --- |
| 执行工单状态命令 | `/production/work-orders` | 保持当前页并显示新状态 | 关闭原因对话框 |

## 状态与不变量

- `pending → running`：开始。
- `running → paused`：暂停，必须有原因。
- `paused → running`：继续。
- `pending/running/paused → exception`：上报异常，必须有原因。
- `exception → pending/running`：恢复，必须有处置说明。
- 工单 `pending/running/paused/exception` 分别投影为批次 `released/running/paused/exception`。
- 每次命令必须带客户端最后读取到的 revision 和唯一 `Idempotency-Key`。
- 命令事件记录组织、真实操作者、工位、设备、前后状态、原因、服务端时间和幂等键，已记录事件不可修改或删除。
- 完工不属于本切片；没有实际产出、损耗和成品批次时不能把工单标记为完成。

## API

- `POST /api/v1/work-orders/:id/start`
- `POST /api/v1/work-orders/:id/pause`
- `POST /api/v1/work-orders/:id/resume`
- `POST /api/v1/work-orders/:id/report-exception`
- `POST /api/v1/work-orders/:id/recover`

详细请求、响应和错误语义见 [生产工单 API 契约](../contracts/work-order-api.md)。

## 失败、迁移与恢复

- 过期 revision、非法状态和批次/工单投影不一致返回 `409`，客户端刷新后再操作。
- 不存在或跨组织工单返回 `404`。
- production 无可信身份返回 `400`，页面禁用命令并说明原因。
- migration 为工单事件增加命令上下文、幂等唯一约束和不可变触发器；既有 `created` 事件保持兼容。
- 应用回滚可保留新增列；结构回退必须通过后续 migration，不删除审计事件。

## 不在本次范围

- 实际领料、投料、退料、报废和库存扣减。
- 实际产出、完工、成品批次、质量放行和入库。
- 离线队列、扫码设备注册、排班和完整身份授权。

## 验收标准

- [x] 五类命令只允许约定状态转换，并校验 revision。
- [x] 工单、生产批次及其审计事件在同一事务中一致提交或回滚。
- [x] 相同幂等键重复提交不产生第二次转换或第二条命令事件。
- [x] 跨组织、非法状态、过期 revision 和 production 无身份均失败关闭。
- [x] development 页面可完成开始、暂停、继续、异常和恢复；刷新后状态保留。
- [x] 页面覆盖 loading、empty、offline、permission、conflict 和移动端操作。
