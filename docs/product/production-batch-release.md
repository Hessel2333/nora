# 生产批次确认与工单释放功能规格

## 目标

生产主管确认计划员建立的生产批次，并基于批次冻结的配方与工序依据释放一张可追溯生产工单。

## 当前问题

生产需求已经可以合批或拆批形成草稿批次，但草稿没有正式确认动作，也不能生成工单。继续使用浏览器 Mock 工单会切断订单、配方快照、批次和现场任务之间的事实链。

## 产品边界与证据

- 目标角色：生产计划员、生产主管、现场员工。
- 当前事实来源：`ProductionBatch`、`DemandAllocation` 和批次冻结的 `recipeSnapshot`。
- Build / Buy / Integrate：批次确认、工单释放和不可变生产依据属于 Nora 核心领域，由 Nora 实现。

## 用户与权限

| 角色 | 可执行动作 | 数据范围 |
| --- | --- | --- |
| 生产计划员 | 查看批次和工单 | 当前组织 |
| 生产主管 | 确认批次、释放工单 | 当前组织 |
| 现场员工 | 查看已释放工单 | 当前组织；执行命令不在本切片 |

当前尚未接真实身份。development 使用显式开发身份；production 拒绝写命令；demo 使用隔离浏览器状态。

## 核心用例

1. 计划员已经建立 `ProductionBatch.draft`。
2. 生产主管核对计划量、计划时间、来源分配和冻结配方后确认批次。
3. 系统把批次原子转换为 `confirmed` 并记录审计事件。
4. 生产主管释放工单。
5. 系统只从批次冻结的 v2 配方快照取得工序和首个工作中心，原子创建一张工单并把批次转换为 `released`。

## 页面入口与出口

| 用户任务 | 入口 | 成功出口 | 取消/返回 | 独立查看入口 |
| --- | --- | --- | --- | --- |
| 确认并释放批次 | `/production/plans` | `/production/work-orders` | 保持当前工作台 | `/production/work-orders` |

## 状态与不变量

- 批次：`draft → confirmed → released`。
- 工单：释放时创建为 `pending`，等待 MES 执行接管。
- 一个批次在本 MVP 中只生成一张工单；数据库唯一约束阻止重复生成。
- 确认和释放必须校验组织、来源状态、revision 和幂等键。
- 工单复制批次商品、数量、单位、计划时间、BOM 版本和完整配方快照。
- 工艺下发只接受 `recipeSnapshot.schemaVersion = 2` 且至少有一个有序工序；历史 v1 快照失败关闭。
- 发布工单不得运行时读取最新 BOM 或商品主数据补齐字段。

## 数据模型

| 实体 | 关键字段 | 所有权 | 生命周期 |
| --- | --- | --- | --- |
| WorkOrder | 批次、编号、冻结配方、工序、数量、工作中心、状态、revision | Execution & Quality | 批次释放时创建，完成或取消时结束 |
| WorkOrderEvent | 工单、状态、操作者、revision、时间、详情 | Execution & Quality | 随工单永久保留 |
| ProductionBatchEvent | 命令幂等键、批次 revision、操作者、详情 | Planning | 随批次永久保留 |

## API

- `POST /api/v1/production-batches/:id/confirm`
- `POST /api/v1/production-batches/:id/release`
- `GET /api/v1/work-orders`

命令请求包含 `revision`，并要求 `Idempotency-Key`。详细请求和错误码见 [生产批次 API 契约](../contracts/production-batch-api.md)。

## 非功能要求

- 审计：记录组织、操作者、批次 revision、幂等键、工单编号和服务端时间。
- 安全：所有查询和写入固定带组织边界；production 未接真实身份时拒绝写入。
- 运行模式：development 正式写库；production 失败关闭；demo 只改隔离浏览器状态。
- 响应式：批次动作和工单列表覆盖桌面表格与移动卡片。

## 失败、迁移与恢复

- API 或数据库不可用时页面显示失败并允许重试，不制造成功状态。
- migration 只新增工单表、工单事件表和批次事件幂等字段，不改写已有批次。
- 应用回滚时可保留新增表；删除数据结构必须通过后续可审查 migration。

## 不在本次范围

- 产能求解、多工单拆分、班次和人员排程。
- MES 开工、暂停、完工、实际投料、产出、质量与库存写入。
- 批次取消及其来源需求数量回补。

## 验收标准

- [x] 草稿批次可确认，确认后的 revision 和审计事件一致增加。
- [x] 未确认批次不能释放工单。
- [x] 确认批次可释放且只生成一张来源明确的工单。
- [x] v1 或不完整配方快照不能释放。
- [x] 重复幂等键不产生第二次转换或第二张工单。
- [x] 过期 revision、跨组织对象和数据库失败不会留下部分状态。
- [x] development 页面读取真实批次和工单；production 写命令失败关闭；demo 与正式数据隔离。

## 必需证据

- 自动化测试：批次 Policy、Service、工单查询和前端类型检查。
- 数据库：可读 migration、唯一约束、Decimal 数量和空库迁移。
- 浏览器：生产准备确认/释放、真实工单列表、错误和空状态。
- 文档：本规格、API 契约、批次与工单状态机。
