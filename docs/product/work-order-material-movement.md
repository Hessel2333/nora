# 生产工单领料与退料功能规格

## 目标

仓储人员从已放行库存批次向真实生产工单领料，并在未使用时退回原库位和原批次，让库存余额、冻结配方需求和工单因果链可核验。

## 当前问题

工单已经能够开始、暂停和处理异常，但现场用掉哪些库存批次仍没有正式记录。若只在页面上改变进度，库存不会扣减，原料批次也无法追踪到工单。

## 用户与权限

| 角色 | 可执行动作 | 数据范围 |
| --- | --- | --- |
| 仓储人员 | 查看工单物料、选择批次、领料、退料 | 当前组织和授权库位 |
| 现场操作员 | 查看已领物料与来源批次 | 当前组织和当前工位 |
| 生产主管 | 查看计划需求、净领用和异常 | 当前组织 |

production 在可信身份与库位权限接入前继续拒绝写入；development 使用明确开发身份和设备上下文验证完整事务。

## 核心用例

1. 系统只从工单冻结的完整 v2 配方快照递归计算叶子原料需求，按工单计划产量缩放并向上取整到 3 位小数。
2. 仓储人员选择一个已放行、未失效且有余额的库存批次，输入本次领料数量。
3. 服务端锁定余额行，在一个 Serializable 事务中追加 `issue/outbound` 流水并扣减余额。
4. 领料数量不能超过工单该原料剩余计划需求，也不能超过库存批次余额。
5. 退料必须回到原产品、原批次和原库位，累计退料不能超过扣除实际耗用和报损后的待核销量；事务追加 `return/inbound` 流水并增加余额。
6. 相同幂等键重复提交返回同一流水和余额，不重复扣减或归还。

## 页面入口与出口

| 用户任务 | 入口 | 成功出口 | 取消/返回 |
| --- | --- | --- | --- |
| 查看并领退料 | `/production/work-orders` 的“领退料” | 对话框内刷新需求、批次余额和流水 | 关闭对话框 |

## 状态与不变量

- 领料允许工单状态：`pending`、`running`、`paused`；异常、已完成或已取消工单不能新增领料。
- 退料允许工单状态：`pending`、`running`、`paused`、`exception`；已完成或已取消工单不能退料。
- 领用产品必须存在于工单冻结配方递归叶子需求，禁止读取当前 BOM 补齐或替换。
- 首版不做单位换算；冻结需求单位、产品库存基础单位和流水单位必须完全一致。
- 库存批次必须 `released` 且未失效才能领料；退料后批次沿用当时质量状态，不自动放行。
- 余额行由数据库锁和 revision 双重保护，禁止负库存。
- 每条流水绑定 `workOrderId`，同时记录组织、库位、产品、批次、操作者、工位、设备、服务端时间和幂等键。
- 领料仅表示仓库向生产发料，不等于实际耗用；实际耗用与报损按[物料核销规格](./work-order-material-usage-reconciliation.md)追加事实，退料不覆盖原流水。

## API

- `GET /api/v1/inventory/work-orders/:id/materials`
- `POST /api/v1/inventory/work-orders/:id/issues`
- `POST /api/v1/inventory/work-orders/:id/returns`

详细请求、响应和错误语义见 [库存 API 契约](../contracts/inventory-api.md)。

## 失败、迁移与恢复

- 过期余额 revision、库存不足、超计划领料、超量退料和工单状态变化返回 `409`。
- 工单/余额不存在或跨组织返回 `404`。
- 冻结配方不完整或单位不一致返回 `422`，不回退到主数据。
- migration 为库存流水增加工单外键、工位和设备上下文；历史期初流水保持兼容。
- 结构回退必须使用后续 migration；既有库存流水不可删除或修改。

## 不在本次范围

- 工序级/阶段级投料、替代料审批和库存报废处置；工单级实际耗用与报损已由独立核销切片覆盖。
- 自动 FEFO 分配、库存预占、跨单位换算、调拨和离线扫码队列。
- 实际产出、完工、成品批次、质量放行和入库。

## 验收标准

- [x] 物料需求只来自冻结 v2 配方，并按计划数量正确缩放。
- [x] 领料原子追加出库流水和扣减余额；重复提交不重复扣减。
- [x] 退料原子追加入库流水和增加余额；不能超过同批次净领用量。
- [x] 跨组织、非法状态、非配方原料、非放行/过期批次、单位冲突、库存不足和并发冲突失败关闭。
- [x] development 页面可按近效期选择批次领料并从已领批次退料，刷新后仍保留。
- [x] 页面覆盖 loading、empty、error、permission、conflict 和移动端操作。
