# 配方工艺工作台：纵向功能规格

## Outcome

配方工程师可以在同一个版本工作台中维护层级物料结构、有序前处理步骤和阶段投料；计划与审核流程可以冻结完整的物料与前处理依据，现场人员不需要从备注中猜测“验收、洗、切、腌、组配、分装”的顺序。Nora 的流程在净配菜成品完成分装、复核并进入冷链暂存时结束。

## Actor

- 配方工程师：建立草稿、维护工序和阶段投料、发布版本。
- 生产主管：查看当前/历史工艺与物料展开，判断能否进入生产准备。
- 审核人员：审批订单时冻结当时有效的完整配方依据。

## Current problem

- 现有版本只记录物料，无法表达清洗、切配、腌制等顺序。
- 同一物料受数据库唯一约束，无法在不同工序重复投放。
- 关系图与日常核对任务脱节，节点多时难以稳定阅读，缩放还会破坏页面操作。
- 大面积深色区块削弱数据层级，主按钮链接的全局颜色规则破坏了白字对比度。

## In scope

- 在 `BomVersion` 下建立有序、版本化的 `BomOperation`。
- 每条 `BomItem` 必须绑定一个投料工序；同一物料可在不同工序重复出现。
- 草稿可原子更新工序、阶段投料与产出基准；发布后不可原地修改。
- 复制版本时复制工序并重建投料引用。
- 审批快照 v2 冻结工序和每条用料的投料工序。
- 工作台以可展开、可筛选、行与详情联动的逻辑 BOM 表为主视图，并提供前处理路线和阶段投料编辑。
- 提供叶菜、根茎、肉类基础、肉类腌制、配菜包组配等标准流程模板；模板用于生成可编辑骨架，保存的正式事实仍是版本化工序。
- 移除普通员工主线中的自由缩放关系图；层级浏览、损耗筛选和配方用量试算分别由稳定的任务视图承载。
- 收敛订单交接和配方头部的大面积深色背景。

## Non-goals

- 不实现工位排程、设备参数下发、HACCP 放行、实际投料或实际产出。
- 不实现工序分支、并行路径、返工路径和副产物。
- 不实现完整 UOM、密度换算和包装换算。
- 不在本轮建立可由后台治理的流程模板主数据；模板先作为产品内置标准库，后续如需组织级差异再单独建模。
- `workCenter` 仍是版本快照文本；工厂/工位主数据另行建模。

## Domain rules

1. 工艺路线和物料结构是不同领域事实，但由同一个配方版本治理并在工作台融合呈现。
2. 工序 `code` 和 `sequence` 在一个版本内唯一；顺序按 `sequence` 升序。
3. 每条用料必须绑定同版本工序；跨版本工序 ID 不得引用。
4. 同一物料允许在不同工序或同一工序多次出现，每一行保留独立数量、损耗和备注。
5. 发布必须至少包含一个工序和一条用料，且所有用料均已分配工序。
6. 版本复制生成新的工序 ID，并把用料重新指向新版本工序。
7. 旧历史版本无法还原真实工艺时，只能标记“历史配料”，不得编造清洗/切配数据。
8. 已审核订单继续读取不可变快照；不得因当前工艺变化重新解析。
9. 工序类型采用净配白名单：`receive/wash/cut/marinate/mix/cool/pack/quality`。数据库枚举、API DTO、快照校验和编辑器选项必须使用同一白名单，不能保留未启用的最终加热类型或历史兼容入口。
10. 最终加热制作、热菜、热厨、灶台以及对应产线、工位、设备参数和温度曲线均不进入配方、模板、Mock、seed 或 Showroom。
11. 配方页的用量试算只接收当前配方版本与目标产出，不接收销售订单，也不合并其他商品。整单物料汇总属于订单与生产需求上下文；半成品递归展开仍属于当前配方结构。

## Acceptance scenarios

### 编辑完整工艺

Given 一个草稿版本
When 配方工程师应用“肉类腌制前处理”，形成“来料确认 → 修整切配 → 低温腌制 → 复核称重 → 分装贴标”，并将物料分配到相应步骤后保存
Then API 在单个事务内替换定义、revision 增加，工作台按顺序展示路线和阶段投料。

### 重复阶段投料

Given 白砂糖已在“腌制”工序使用
When 工程师再次把白砂糖添加到“称重组配”步骤
Then 两条用料都能保存，并分别参与物料展开汇总。

### 拒绝不完整发布

Given 草稿没有工序或存在未分配工序的用料
When 用户发布
Then 服务端拒绝发布，当前有效版本和审批快照不受影响。

### 冻结审批依据

Given 订单交付时点存在有效配方 v2
When 订单审批
Then快照包含有序工序、每条用料的 `operationCode` 和递归子配方；后续发布新版本不改变该快照。

### 逻辑表交互

Given 用户正在查看多层 BOM
When 搜索物料或工序、筛选“有损耗/含下级”、展开收起层级并选择一行
Then 表格保持稳定列关系，所选行的工序、用量、损耗、成本和直接下级在详情区同步更新，页面不依赖画布缩放完成核对。

### 配方用量试算隔离

Given 用户正在查看某个菜品的配方版本
When 调整目标产出并查看末级物料
Then 系统只放大当前配方及其递归半成品，不显示订单选择器，也不引入其他菜品；整单需求从订单详情进入。

Given 用户从订单中心打开一张待审核的多商品订单
When 查看订单物料
Then 订单详情可以按当前有效配方合并整单末级物料，并明确标记为审核前试算；审核通过后只读取冻结快照。

### 拒绝白名单外步骤

Given 一个净菜配方草稿
When 调用方提交不在净配白名单中的工序类型
Then DTO 在进入领域事务前拒绝请求，数据库枚举也无法持久化该值；工作台和标准模板不提供对应选项。

## Data and contract impact

- 新增 `BomOperationKind`、`bom_operations`。
- `bom_items.operation_id` 为必填外键；移除“版本内组件唯一”约束。
- BOM 读写契约新增 `operations[]` 与 `items[].operationCode`。
- `ProductionDemandLine.recipeSnapshot` 新写入 schema v2；v1 保持只读兼容。

## Permission and audit

沿用当前 MVP 的组织边界和审计操作者解析。工序与用料随版本更新事件一起写入；未来接入身份系统后必须记录真实用户和设备，不新增前端直改正式状态的入口。

## Failure and offline behavior

- development/production 下 API 离线时保存和发布必须失败，不写入浏览器本地状态。
- revision 冲突返回冲突错误，界面保留草稿输入并提示刷新后处理。
- API 替换定义失败时事务回滚，不能留下只有工序或只有用料的半成品版本。

## Migration and rollback

- 已知 `NORA-DEMO` 本地样例按可核对的净配步骤前向纠正，并记录版本迁移事件。
- 若非演示组织存在白名单外的历史工序或审批快照，迁移必须中止并由数据所属组织制定审计修复方案，不得静默改写真实生产依据。
- 其他历史版本创建明确的“历史配料”迁移工序，并把原用料关联到该工序。
- 回滚采用数据库恢复或向前修复；删除工序表会丢失新版本工艺，不提供破坏性自动 down migration。

## Required evidence

- 空库 migration 与重复 seed。
- API 服务测试：创建、复制、更新、发布守卫和 v1/v2 快照兼容。
- Web 类型检查、单测、构建。
- 桌面与移动端浏览器检查：逻辑 BOM 表、层级交互、标准流程、编辑态表格、按钮对比度、错误状态和控制台。
