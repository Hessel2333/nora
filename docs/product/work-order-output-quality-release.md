# 生产工单产出、质检与成品入库功能规格

## 目标

现场操作员申报真实产出批次，质量人员完成可追溯判定；只有合格批次才原子进入成品库存并完成工单。

## 当前问题

工单能够执行和领退料，但“做出了多少、对应哪个成品批次、谁判定合格、何时进入库存”仍没有正式事实。若直接把工单改为已完成，质量与库存会失去因果链；若先增加库存再补质检，不合格品可能被当作可用库存。

## 产品边界与证据

- 目标角色：现场操作员、质量人员、生产主管、仓储人员。
- 当前事实来源：真实工单、冻结 v2 配方、库存库位、库存批次、追加式库存流水。
- Build / Buy / Integrate：产出、质量判定和入库之间的事务边界是 Nora 的生产核心；实验室检测设备与附件存储后续通过集成完成。

## 用户与权限

| 角色 | 可执行动作 | 数据范围 |
| --- | --- | --- |
| 现场操作员 | 对生产中工单申报产出批次 | 当前组织和授权工位 |
| 质量人员 | 查看待检批次、记录抽样与检查结果、放行或拒收 | 当前组织和授权工厂 |
| 生产主管 | 查看产出、质量历史和异常 | 当前组织 |
| 仓储人员 | 查看放行后形成的成品库存与流水 | 当前组织和授权库位 |

production 在可信身份与角色权限接入前继续拒绝写入；development 使用明确开发身份、工位和设备验证真实事务。

## 核心用例

1. 生产中工单先完成冻结叶子原料的领料与耗用/报损/退料核销，再申报一个产出批次，填写实际数量、批次号、有效期和数量差异原因；系统创建待检库存批次，但不增加库存余额。
2. 质量人员依据工单冻结工艺温度范围和现场质量标准，记录标准版本、抽样数量、实测温度、外观、封口和标签结果。
3. 合格判定在一个 Serializable 事务中追加质量记录、放行库存批次、追加成品入库流水、增加余额，并把工单与生产批次置为完成。
4. 不合格判定保留产出与检查记录，将批次置为不合格、工单与生产批次置为异常，不增加库存；主管恢复生产后可申报新的产出批次。
5. 相同幂等键重复提交返回同一结果，不新增第二个批次、检查、流水或状态事件。

## 状态与不变量

- 工单：`running → awaiting_quality → completed`；不合格为 `awaiting_quality → exception`。
- `running → awaiting_quality` 前，每类冻结叶子原料必须满足 `计划 = 净领用 = 实际耗用 + 报损`；未领齐或存在待核销量时拒绝报产。
- 生产批次与工单状态投影必须一致。
- 每张工单同一时间最多一个待检产出；已放行后不得再申报产出。
- 产出数量和库存数量使用 Decimal；首版不做单位换算，工单、商品和流水单位必须一致。
- 实际数量与计划数量不同时必须填写差异原因。
- 库存批次在报产时为 `pending`；只有质量放行事务可改为 `released` 并新增 `produce/inbound` 流水。
- 不合格批次为 `rejected` 且账面数量为零；后续报废、返工和让步接收不在本次范围。
- 质量检查只追加；撤销与重判不得覆盖历史记录。
- 并发策略：工单与产出行锁、revision 乐观锁、组织内幂等唯一约束和 Serializable 事务。

## 数据模型

| 实体 | 关键字段 | 所有权 | 生命周期 |
| --- | --- | --- | --- |
| `WorkOrderOutput` | 工单、成品批次、实际数量、单位、状态、报产上下文、revision | Execution | 报产创建，质量判定更新状态 |
| `QualityInspection` | 产出、标准版本、抽样、测量值、检查项、判定、人员与设备 | Quality | 每次判定追加，禁止修改删除 |
| `InventoryLot` | 商品、批次号、质量状态、生产与有效时间 | Inventory | 报产创建，质量判定更新状态 |
| `InventoryTransaction` | `produce/inbound`、产出来源、库位、批次、数量与幂等键 | Inventory | 合格放行时追加，不可修改 |

## 非功能要求

- 性能：单工单返回最近 20 条产出及其检查；工单列表不串行预取详情。
- 审计：记录组织、真实操作者、工位、设备、服务端时间、revision、幂等键与原因。
- 安全：服务端组织边界；production 缺可信身份时失败关闭。
- 可观测性：稳定错误码区分输入、组织、状态、revision 与并发冲突。
- 运行模式：demo 保持显式演示交互；development 调用本地真实服务；production 未接身份时只读。
- 无障碍/响应式：对话框可键盘操作，错误使用 `role=alert`，移动端表单单列且按钮至少 44px。

## 失败、迁移与恢复

- 依赖不可用时页面显示错误并允许保留输入重试，不产生浏览器本地成功事实。
- migration 新增产出、质量表和工单待检状态；历史工单无需回填产出。
- 事务任一步失败，产出、质量、库存和状态均回滚。
- 结构回退使用后续 migration；已写入的质量与库存事实不得删除。

## 不在本次范围

- 工序级/阶段级投料、库存报废处置、返工路线、让步接收、质量附件和实验室设备集成；工单级实际耗用与报损已由物料核销切片覆盖。
- 多次部分报产后累计完工、跨单位换算和成品批次拆合。
- 完整质量标准主数据；首版保存现场使用的标准版本标识，并以冻结工艺温度范围作为机器可校验的温度依据。

## 验收标准

- [x] 生产中工单报产后形成待检产出与待检批次，库存余额不增加。
- [x] 合格放行原子产生质量记录、放行批次、成品入库流水、余额与工单/批次完成状态。
- [x] 不合格原子产生质量记录、拒收批次与异常状态，库存余额仍为零。
- [x] 温度超出冻结工艺范围、检查项失败时不能选择合格放行。
- [x] 重复提交、失败回滚、跨组织、过期 revision、非法状态和 production 无身份均失败关闭或幂等返回。
- [x] development 页面覆盖 loading、empty、error、permission、conflict 和移动端操作；demo 与正式路径可区分。
