# 库存台账底座与期初入账功能规格

## 目标

仓储主管把上线时已经存在的实物库存按库位和批次登记为不可变库存流水，并让计划与现场能够读取可信的批次余额。

## 当前问题

工单已经能够从冻结配方释放，但仓库库存仍来自 `Product.stock` 或演示数据。现场若在此基础上扫码领料，会缺少原料批次、库位、效期和可核验余额，既不能防止重复扣减，也不能完成召回。

## 产品边界与证据

- 目标角色：仓储主管、库存管理员、生产计划员。
- 当前事实来源：`Product` 主数据和本切片新增的 `InventoryLocation`、`InventoryLot`、`InventoryTransaction`、`StockBalanceProjection`。
- Build / Buy / Integrate：批次库存事实和生产领退料语义属于 Nora 核心追溯链；通用扫码硬件和外部 ERP 库存导入后续通过适配器集成。

## 用户与权限

| 角色 | 可执行动作 | 数据范围 |
| --- | --- | --- |
| 仓储主管 | 查看库存、登记期初库存 | 当前组织 |
| 生产计划员 | 查看可用库存与效期 | 当前组织 |
| 现场员工 | 后续扫码领料时选择库存批次 | 当前组织和授权库位；本切片只读 |

当前身份认证尚未接入：development 使用显式开发身份；production 拒绝写入；demo 不把浏览器数据写入正式台账。

## 核心用例

1. 仓储主管选择现有库位和产品，录入实物批次、数量、收货日期、效期和质量状态。
2. 系统校验产品单位、组织边界、批次唯一性和正数数量。
3. 系统在一个事务中创建库存批次、期初入账流水和余额投影。
4. 重复提交相同 `Idempotency-Key` 返回同一结果，不重复增加余额。
5. 库存页面按产品、库位、批次、质量状态和效期展示账面数量；可用量只统计已放行批次。

## 页面入口与出口

| 用户任务 | 入口 | 成功出口 | 取消/返回 | 独立查看入口 |
| --- | --- | --- | --- | --- |
| 查看批次库存 | `/inventory/stock` | 保持当前页 | — | `/inventory/stock` |
| 登记期初库存 | `/inventory/stock` | 关闭对话框并刷新余额 | 关闭对话框 | `/inventory/stock` |

## 状态与不变量

- 库存流水只追加，不修改或删除；纠错后续通过反向流水实现。
- 每条流水数量必须为正 Decimal；方向决定余额增减。
- 余额投影只能与流水在同一数据库事务内更新，可从流水重建。
- `organization + idempotencyKey` 全局唯一；`organization + lotCode` 唯一。
- 同一批次只能属于一个产品；流水单位必须与产品库存基础单位一致。
- 当前禁止负库存；后续领料命令必须锁定余额行后再校验。
- `Product.stock` 不参与正式库存查询。

## 数据模型

| 实体 | 关键字段 | 所有权 | 生命周期 |
| --- | --- | --- | --- |
| InventoryLocation | 组织、工厂、编码、名称、类型、启用状态 | Inventory & Traceability | 主数据 |
| InventoryLot | 组织、产品、批次号、供应商批次、收货/生产/失效时间、质量状态 | Inventory & Traceability | 首次入账创建，永久追溯 |
| InventoryTransaction | 组织、库位、产品、批次、类型、方向、数量、单位、来源、操作者、幂等键、服务端时间 | Inventory & Traceability | 仅追加 |
| StockBalanceProjection | 组织、库位、产品、批次、账面数量、revision | Inventory & Traceability | 随流水原子更新，可重建 |

## API

- `GET /api/v1/inventory/locations`
- `GET /api/v1/inventory/stock`
- `GET /api/v1/inventory/transactions`
- `POST /api/v1/inventory/opening-balances`

详细请求、响应和错误语义见 [库存 API 契约](../contracts/inventory-api.md)。

## 非功能要求

- 性能：库存和流水首个 MVP 最多返回最近/最相关 200 行，并提供产品、库位和质量状态筛选。
- 审计：流水记录真实操作者、幂等键、业务来源和服务端时间。
- 安全：所有查询和写入由服务端固定组织边界；production 未接身份时失败关闭。
- 运行模式：demo 使用明确演示数据；development 读写本地 API；production 只读真实 API且写入失败关闭。
- 无障碍/响应式：桌面使用可横向滚动表格，移动端使用批次卡片；对话框焦点受控，错误通过 `role=alert` 播报。

## 失败、迁移与恢复

- API 或数据库不可用时显示失败并允许重试，不在浏览器制造余额。
- migration 只新增库存表、枚举、索引、检查约束和流水不可变触发器，不回填 `Product.stock`。
- 现有实物库存必须由仓储主管盘点后期初入账，不把历史演示字段自动转换为正式事实。
- 代码回滚可保留新增表；结构回退必须使用后续 migration，流水不得直接删除。

## 不在本次范围

- 采购收货、供应商与到货质检。
- 工单扫码领料、退料、报废、调拨和成品入库。
- 质量放行命令、库存预占、完整单位换算和负库存策略配置。
- 离线队列、真实扫码设备和外部 ERP 导入。

## 验收标准

- [ ] Given 有效库位和产品 / When 登记期初库存 / Then 同一事务产生批次、流水和相等余额。
- [ ] 相同幂等键重复提交不重复建批次或增加余额。
- [ ] 批次重复、单位不符、非正数量、跨组织资源和事务失败不留下部分写入。
- [ ] 正式库存查询完全来自余额投影，不读取 `Product.stock`。
- [ ] 页面覆盖 loading、empty、error、筛选、重复提交和 production 写入禁用。
- [ ] Demo 与 development/production 的数据路径和身份提示可区分。

## 必需证据

- 自动化测试：DTO、Service 成功/幂等/边界、组织查询和前端库存视图纯函数。
- 数据库：可读 migration、Decimal、唯一/检查约束、不可变流水触发器、空库迁移和重复 seed。
- 浏览器：桌面/移动库存列表、期初入账成功、错误和空状态。
- 文档：本规格、库存 API 契约、领域文档、Roadmap 和验证记录。
