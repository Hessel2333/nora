# 生产需求工作台功能规格

## 目标

让计划员从已审核订单形成的真实生产需求中，快速识别交付优先级、配方快照完整性和下一步处理对象。

## 当前问题

订单审核已经能够原子创建生产需求，但生产侧只有静态甘特演示。审核人无法确认需求编号，计划员也没有 API 支撑的需求队列，只能在订单与演示计划之间反复查找，容易把“已审核”误认为“已经排产”。

## 产品边界与证据

- 目标客户/角色：订单审核人、生产计划员、生产主管。
- 当前事实来源：`production_demands`、`production_demand_lines`、关联销售订单和审核时冻结的配方快照。
- Build / Buy / Integrate：生产需求及订单来源关系是 Nora 核心领域事实，由 Nora 实现；排程求解器和完整 ERP/WMS 仍为后续集成边界。

## 用户与权限

| 角色 | 可执行动作 | 数据范围 |
| --- | --- | --- |
| 订单审核人 | 审核通过后查看生产需求编号与就绪结果 | 当前组织的待审核订单和新建需求 |
| 生产计划员 | 搜索、筛选、查看需求来源、交期和快照阻断 | 当前组织的生产需求 |
| 生产主管 | 查看需求准备状态和来源订单 | 当前组织的生产需求 |

当前 MVP 尚未接入真实身份与授权。development 使用显式开发身份；production 只开放只读需求查询，审核写入继续失败关闭。

## 核心用例

1. 订单处于 `pending`，审核人完成审核。
2. 服务端在同一事务中批准订单并创建一张生产需求及需求行。
3. 审核页返回待审核列表，显示真实需求编号和“待计划”结果。
4. 计划员进入生产准备，按订单、客户、商品或需求号检索。
5. 计划员优先处理配方快照不完整或临近交付的需求，并可回到来源订单或配方工作台核对。

## 页面入口与出口

| 用户任务 | 入口 | 成功出口 | 取消/返回 | 独立查看入口 |
| --- | --- | --- | --- | --- |
| 审核订单 | `/orders/:id/review` | `/orders/approvals?result=approved` | `/orders/approvals` | `/orders/:id` |
| 查看生产准备 | `/production/plans` | 保持当前需求选择 | `/orders` | `/production/plans` |
| 核对来源订单 | `/production/plans` | `/orders/:id` | `/production/plans` | `/orders/:id` |
| 核对配方 | `/production/plans` | `/catalog/boms/:bomId` | `/production/plans` | `/catalog/boms` |

路由 `/production/plans` 为现有入口的兼容路径。本阶段页面和导航使用“生产准备”，不把需求队列描述为已经完成的生产计划。

## 状态与不变量

- 本次只读取 `pending_planning`、`partially_planned`、`planned`、`completed`、`cancelled`，不新增状态转换。
- 一张销售订单至多对应一张生产需求；重复审核不得创建第二张需求。
- 所有查询必须带组织边界。
- 页面就绪状态只根据持久化的审批配方快照判断，不运行时读取最新 BOM 推断历史结果。
- 商品数量单位可能不同，页面不得把不同单位直接求和为总产量。

## 数据模型

| 实体 | 关键字段 | 所有权 | 生命周期 |
| --- | --- | --- | --- |
| ProductionDemand | code、salesOrderId、factory、requiredAt、status | 生产需求 | 订单审核通过时创建，后续由计划/执行显式迁移 |
| ProductionDemandLine | 来源订单行、商品、数量、单位、配方版本与快照 | 生产需求 | 随需求创建并保留历史依据 |
| SalesOrderSummary | 订单号、客户、交期 | 销售与客户只读投影 | 随查询投影，不复制可变对象 |

## API

- `GET /api/v1/production-demands`：按组织分页读取需求，支持状态与关键词筛选。
- `GET /api/v1/orders/:id/production-demand`：读取订单对应的单张需求。

详细响应见 [生产需求 API 契约](../contracts/production-demand-api.md)。

## 非功能要求

- 性能：默认 50 条、最大 100 条，按交期和编号排序；查询与计数在一个数据库事务快照中完成。
- 审计：本次只读不新增审计事件；需求创建继续复用订单审核事务和审核事件。
- 安全：服务端固定带组织边界；production 未接身份时不开放审核写入。
- 运行模式：demo 明确显示演示需求；development/production 只从 API 读取，失败时不回退 Mock。
- 无障碍/响应式：筛选可键盘操作，移动端使用卡片列表，桌面端保留高密度表格和任务侧栏。

## 失败、迁移与恢复

- API 离线：显示失败状态和重试，不保留或制造本地生产需求。
- 历史快照不完整：需求保留在列表并标记阻断，不读取当前 BOM 覆盖历史事实。
- 回滚：移除只读端点和工作台即可；本次没有数据库结构变化。

## 不在本次范围

- 合批/拆批与草稿生产批次已由 [生产批次分配功能规格](./production-batch-allocation.md) 作为后续纵向切片实现，不属于本规格的只读需求工作台验收；产能排程仍未实现。
- 批次确认与一批次一工单释放已由 [生产批次确认与工单释放功能规格](./production-batch-release.md) 作为后续纵向切片实现，不属于本规格的只读需求工作台验收；领料、实际投料、产出、包装执行和成品入库仍未实现。
- 采购建议、库存可用量、供应商、到货和来料质检。
- production 审核写入和角色授权。

## 验收标准

- [ ] Given 待审核订单 / When 审核通过 / Then 列表显示订单号、真实需求编号和待计划结果。
- [ ] Given 当前组织的生产需求 / When 打开生产准备 / Then 只显示 API 返回的当前组织需求。
- [ ] Given 快照不完整的需求 / When 查看列表和侧栏 / Then 显示阻断且不暗示已可排产。
- [ ] Given API 不可用 / When 打开页面或重试 / Then 不回退演示数据且不显示成功状态。
- [ ] Given 不同计量单位的需求行 / When 查看汇总 / Then 不出现跨单位总数量。

## 必需证据

- 自动化测试：生产需求查询组织边界、分页/筛选、快照就绪投影、前端筛选与路由能力。
- 浏览器：桌面与移动需求列表、审核结果、空态和失败态。
- 文档：本规格、API 契约和既有生产需求状态机。
