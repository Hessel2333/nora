# 生产工单物料耗用与报损核销功能规格

## 目标

现场操作员把已领出的每个原料批次登记为实际耗用、报损或退料，并在物料去向完整核销后申报产出，让原料批次到成品批次的事实链可核验。

## 当前问题

现有领料流水只证明仓库已经把原料交给生产，不说明现场实际用了多少、损失多少或还有多少应退。工单当前仍能在没有实际物料去向的情况下报产，无法回答问题成品具体消耗了哪些原料批次，也无法解释损耗。

## 产品边界与证据

- 目标角色：现场操作员、仓储人员、生产主管和质量人员。
- 当前事实来源：工单冻结 v2 配方、工单领退料流水、库存批次与库位、待检产出。
- Build / Buy / Integrate：批次耗用和报产守卫属于 Nora 的生产执行核心；身份授权和离线同步后续集成。

## 用户与权限

| 角色 | 可执行动作 | 数据范围 |
| --- | --- | --- |
| 现场操作员 | 对生产中工单登记实际耗用或报损 | 当前组织、工位和已领批次 |
| 仓储人员 | 领取原料、退回尚未核销的余量 | 当前组织和授权库位 |
| 生产主管 | 查看计划、领用、耗用、报损和待核销差异 | 当前组织 |
| 质量人员 | 查看产出所依据的物料核销结果 | 当前组织和授权工厂 |

production 在可信身份和职责权限接入前继续拒绝写入；development 使用明确开发身份、工位和设备验证真实事务。

## 核心用例

1. 仓储人员按冻结配方领出已放行原料批次，库存余额已在领料时扣减。
2. 现场操作员按原批次登记实际耗用；发生不可回收损失时登记报损并填写原因。
3. 每次核销不能超过该工单、产品、库位和批次的“领料减退料减既有核销”余量。
4. 仓储退料只能退回尚未耗用或报损的余量，不能把已核销数量重新加回库存。
5. 报产前，每类冻结叶子原料必须领齐计划数量，且每个已领批次必须全部归入耗用、报损或退料。
6. 相同幂等键重复提交返回同一核销事实，不重复记录数量。

## 页面入口与出口

| 用户任务 | 入口 | 成功出口 | 取消/返回 | 独立查看入口 |
| --- | --- | --- | --- | --- |
| 领料与核销 | `/production/work-orders` 的“工单物料” | 对话框内刷新计划、批次和待核销量 | 关闭对话框 | `/production/work-orders` |
| 申报产出 | `/production/work-orders` 的“产出质检” | 物料核销完整后进入待检 | 关闭对话框 | `/production/work-orders` |

## 状态与不变量

- 实际耗用和报损只允许 `WorkOrder.running`；暂停、异常、待检、完成和取消状态均拒绝新增核销。
- 核销产品必须来自工单冻结 v2 配方的递归叶子需求，单位必须等于冻结需求和产品库存基础单位。
- `领料 - 退料 = 实际耗用 + 报损 + 待核销`，四项都使用 Decimal，`待核销` 不得为负。
- 报损必须填写 1–500 字符原因；实际耗用可填写备注。
- 核销是领出后去向事实，不是第二次出库；它不得修改库存余额或新增库存流水。
- 退料继续追加 `return/inbound` 流水并增加余额，但最大可退量必须扣除已耗用和已报损数量。
- 报产守卫要求每类原料净领用等于冻结计划需求，且待核销量为零。
- 核销事实只追加、不可修改或删除；纠错与反向核销不在首版范围。
- 并发策略：锁定工单、组织内唯一幂等键、Serializable 事务；退料和核销共享同一工单锁。

## 数据模型

| 实体 | 关键字段 | 所有权 | 生命周期 |
| --- | --- | --- | --- |
| `WorkOrderMaterialUsage` | 工单、产品、库存批次、原库位、处置类型、数量、单位、原因、操作者、工位、设备、幂等键、服务端时间 | Execution | 核销时追加，永久不可变 |
| `InventoryTransaction` | 领料与退料流水 | Inventory | 领退料时追加，永久不可变 |
| `WorkOrderOutput` | 实际产出与成品批次 | Execution | 物料完整核销后才允许创建 |

## API

- `POST /api/v1/work-orders/:id/material-usages`
- `GET /api/v1/inventory/work-orders/:id/materials` 增加耗用、报损、待核销汇总和最近核销事实。
- `POST /api/v1/inventory/work-orders/:id/returns` 的最大退料量扣除耗用与报损。
- `POST /api/v1/work-orders/:id/outputs` 增加完整核销守卫。

详细请求、响应和错误语义见 [生产工单 API 契约](../contracts/work-order-api.md) 与 [库存 API 契约](../contracts/inventory-api.md)。

## 非功能要求

- 性能：单工单读取最近 200 条领退料和核销事实；独立查询并行执行。
- 审计：记录组织、真实操作者、工位、设备、原批次、库位、处置、原因、幂等键和服务端时间。
- 安全：服务端固定组织边界；production 缺可信身份时失败关闭。
- 运行模式：demo 保持显式演示；development 调用真实本地服务；production 在身份接入前只读。
- 无障碍/响应式：表单可键盘操作，错误使用 `role=alert`，移动端使用单列与至少 44px 触控目标。

## 失败、迁移与恢复

- 非法状态、超量核销、超量退料和报产前未核销返回 `409`；非配方原料或单位冲突返回 `422`。
- migration 只新增追加式核销表，不回填历史工单，也不把领料推断成实际耗用。
- 事务失败不留下部分核销；同一幂等键可安全重试。
- 结构回退使用后续 migration；既有核销事实不得删除。

## 不在本次范围

- 工序级/阶段级投料、扫码称重设备、离线队列、替代料审批和超计划领料。
- 核销纠错、返工、报废库存处置、成本层、跨单位换算和副产物。
- 采购收货与供应商来料质检。

## 验收标准

- [x] 实际耗用和报损只针对生产中工单的已领批次，且不能超过待核销量。
- [x] 报损无原因、跨组织、非配方原料、单位冲突和重复幂等键均按契约处理。
- [x] 已核销数量不能退料；退料与核销并发不会产生负待核销量。
- [x] 未领齐或存在待核销量时不能报产，完整核销后原报产流程可继续。
- [x] 成品批次可经工单追溯到实际耗用和报损的原料批次。
- [x] development 页面覆盖 loading、empty、error、permission、conflict 和移动端操作。
