# AI 协作指南

本仓库允许使用 AI 辅助分析和实现，但 AI 不是业务事实来源、产品负责人或审批人。

## 工作前

1. 阅读根 `AGENTS.md`、`PRODUCT.md`、`ROADMAP.md` 和目标目录最近的 `AGENTS.md`。
2. 从 `docs/index.md` 定位相关术语、上下文、状态机、契约和 ADR。
3. 用模板写清用户结果、非目标、权限、失败路径、幂等和验收。
4. 检查工作树与最近提交，不覆盖他人未提交修改。

## 实现时

- 先保护不变量，再写页面；跨上下文先定契约。
- 不根据页面视觉推断后端已完成，不把 Mock 迁入生产路径。
- 不把会议纪要、功能表或聊天内容自动升级为规范。
- 数据库变化必须提交 migration 和历史数据策略。
- 不能确认的身份、权限、许可证、业务舍入或成本规则应显式阻断并交给人决策。
- 对外部开源能力只引用官方资料；采用前复核版本和许可证。

## 交付时

- 运行与风险相称的 typecheck、lint、test、build、migration、seed、smoke 和浏览器验收。
- 在 PR 中记录改了什么、为什么、没做什么、证据、数据影响与恢复方式。
- 说明哪些页面仍是 Demo，哪些写入需要真实身份/后端。
- 不自动合并、不修改分支保护、不选择许可证、不发布到外部环境，除非用户明确授权。

## 并行协作

按垂直业务切片分工，避免多人同时修改同一聚合根。先冻结术语、数据契约和状态机，再并行实现 API、UI、测试与文档；集成负责人必须重新运行全量验证。
