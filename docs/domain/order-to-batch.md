# 门店订单到生产批次

## 主流程

1. 门店或客户提交订单草稿。
2. 计划员复核交付时间、产品、数量与单位。
3. 审批服务按交付时点选择有效配方版本，并递归冻结完整配方快照。
4. 系统在同一事务中生成一条生产需求；重复审批返回既有结果。
5. 计划员按生产日期、产品、工厂和约束合并或拆分生产需求。
6. 已确认计划生成生产批次与工单。
7. 现场事件、质量结果和库存移动沿订单/需求/批次/工单标识回链。

## 不变量

- 只有已审批订单可以生成生产需求。
- 一个订单最多存在一个有效的源生产需求，必须由数据库唯一约束兜底。
- 审批失败时，订单状态、审计记录、快照和生产需求全部回滚。
- 配方快照不完整时不得继续展开物料需求。
- 合并生产需求不能丢失原始订单行和客户去向。
- 计划数量与单位必须显式，禁止默认把“份”“千克”“箱”视为可直接相加。

## 失败与恢复

- 找不到交付时点的有效配方：审批失败，并返回具体产品与时间。
- 配方递归或单位不可换算：审批失败，要求修复主数据后重试。
- 重复请求：依据订单与幂等键返回既有需求，不重复创建。
- 排产求解失败：保留生产需求，允许人工排程，不伪造“已优化”。
