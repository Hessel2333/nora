# 库存、批次与台账

## 目标模型

库存数量来自不可变的追加式台账，而不是可随意覆盖的产品余额字段。

每条台账事件至少包含：组织、工厂、库位、产品、库存批次、方向、数量、基础单位、业务原因、来源单据、操作者、发生时间和幂等键。

## 典型事件

- 采购收货、退货
- 生产领料、退料
- 半成品/成品入库
- 调拨出入
- 盘盈盘亏
- 报废、质量冻结与放行
- 销售出库

## 不变量

- 已记账事件不可修改或删除；纠错使用反向事件和新事件。
- 每个业务操作必须有稳定幂等键，重试不得重复记账。
- 余额是台账投影，可重建并与事件总和核对。
- 批次必须保留来源和去向；拆分、合并仍保留父子关系。
- 是否允许负库存是组织级显式策略，不得因并发偶发穿透。

## 当前状态

当前已实现首个库存纵向切片：

- `InventoryLocation`、`InventoryLot`、追加式 `InventoryTransaction` 和 `StockBalanceProjection` 已有正式 migration。
- 期初入账在一个 Serializable 事务中创建批次、入账流水和相等余额；组织范围、产品单位、正数 Decimal、批次唯一性和幂等键由服务与数据库共同保护。
- 数据库触发器禁止修改或删除已记账流水；余额投影禁止为负，可从流水重建。
- `/inventory/stock` 正式页面只读余额投影，不使用 `Product.stock`；development 支持期初盘点入账，production 在真实身份接入前拒绝写入。

工单领退料已建立首条执行到库存因果链：流水绑定工单、库位、原料批次、工位和设备，余额在 Serializable 事务中锁定更新。它只表示仓库发料/退料，不等于实际投料。

采购收货、实际投料、调拨、报废、质量放行、成品入库、库存预占、自动 FEFO 分配和投影对账作业仍未实现。并发锁定与完整对账策略继续遵循 [ADR-0004](../decisions/0004-inventory-ledger.md)。
