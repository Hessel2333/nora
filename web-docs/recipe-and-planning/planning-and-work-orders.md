# 从需求到工单

生产计划负责把订单形成的独立需求，转换为适合工厂执行的生产批次。工单只在计划确认后产生，不由订单审核直接生成。

## 计划员的判断顺序

1. 查看交付日期、产品、工厂和需求来源。
2. 确认配方快照完整，数量与单位可以解释。
3. 结合产能、班次、物料和质量约束决定是否合批。
4. 需要分日期、分产线或分包装规格时拆分需求。
5. 核对每个来源的分配量与剩余量。
6. 确认生产批次后再释放工单。

## 合批时不能丢失什么

多个客户订购同一产品时，可以形成同一生产批次，但必须继续保留：

- 每张来源订单和订单行。
- 各来源分配到批次的数量与单位。
- 客户去向和交付承诺。
- 审核时保存的生产配方依据。

不同单位不能直接相加。需要先使用明确的换算关系，或分别计划。

## 拆分时如何核对

拆分后的已分配量与剩余量之和应等于原始需求量。任何取消或改派都应保留原因、操作者和原分配关系。

## 生产批次与工单

生产批次面向产品、数量和计划日期，工单面向现场需要执行的冻结工艺。当前 MVP 一个生产批次释放一张工单，工单中保留按顺序排列的全部工序与工作中心；未来只有在产线、班次和交接规则明确后才拆成多张工序工单。

历史 v1 配方快照没有工艺步骤，系统会显示“历史快照缺少可执行工艺”并阻止释放，不能用最新配方补写历史依据。

生产准备中的批次确认、工单释放和生产工单列表已经接入 development 后端。MES 开工、暂停、完工、拖拽排程和产能结果若标有“演示”，仍只用于了解目标流程，不作为正式生产记录。
